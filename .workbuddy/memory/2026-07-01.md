# 2026-07-01 工作日志

## 修复 Markdown 编辑器"宽度小折行吞字符"bug（BUGS_TROUBLESHOOTING.md #5）

### 问题
窄终端宽度下，含 Markdown 块级前缀（`- ` / `# ` / `> ` / `1. `）的长段落折行时，续行开头吞字符。

### 根因
`block_prefix_source_widths`（BUG #4 修复引入）给前缀字符返回 `char_width(ch)`（>0），让 wrap_engine 的 `visible_pos` 推进了前缀字符。但 pulldown-cmark 在 inline 解析时消费了前缀（`- `/`# `/`> ` 当 block 事件），渲染产物中不含前缀字符 → `visible_end_char` 比渲染产物实际长度多算前缀字符数 → 续行 `extract_span_range` 切片错位 → 吞字符。

这是 BUG #2 和 BUG #4 修复的冲突点：BUG #2 要求折行走"整行 inline 渲染 + 按 visible char 索引切片"，BUG #4 要求前缀字符按 char_width 算（保留宽度）。两者在 block prefix 行折行场景下冲突。

### 修复
- `block_prefix_source_widths` 改返回 `Option<(Vec<u8>, usize)>`：`(per_char_widths, prefix_chars)`
  - 前缀字符 width 仍为 char_width（保留 BUG #4 修复）
  - prefix_chars = 源码字符数 - 渲染产物字符数（通过 `count_inline_render_chars` 调 `parse_inline_text` 计算）
- `wrap_line_inner` 推进 visible_pos 时跳过前 prefix_chars 个字符：`if ch_width > 0 && idx >= prefix_chars`
- 折行宽度（current_width）和渲染 char 位置（visible_pos）是两个独立累加器，不能共用同一条件

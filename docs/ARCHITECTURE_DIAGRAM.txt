FOR CLIENT-SIDE TRIGGER DETECTION:
──────────────────────────────────

1. User types `**` in textarea
2. BlockSourceEditor onChange fires
3. Detect trigger pattern (simple regex/string matching)
4. Show formatting hint/menu at cursor position
5. User confirms (Enter / click) → apply formatting

FLOW:
  textarea input `**bold**`
        ↓
  onChange → detect "**" trigger
        ↓
  Show formatting UI
        ↓
  Confirm/apply
        ↓
  Re-parse (debounced) → validate via IR
        ↓
  renderSingleBlock() shows updated formatting


FOR SERVER-SIDE VALIDATION:
──────────────────────────────

Option A - Lightweight (Recommended):
  POST /api/parse-suggest
  Input: { source, pos: 14, trigger: "bold" }
  Output: { kind: "strong", inline_range: [9, 16] }

Option B - Full Async Validation:
  Use existing /api/parse
  Compare old IR with new IR
  Detect which Inlines changed
  Return change summary


CHALLENGE: Inline Source Mapping
─────────────────────────────────

Current State: Only Blocks have source ranges
               Inlines don't know their byte offsets

For precise syntax triggers, you'd need:
  - Modify ir.rs to add SourceRange to Inline enum
  - Update parser to track inline byte ranges
  - Serialize inline positions in JSON
  
  Then frontend can do:
    "User is at position 14 in source"
    ↓ lookup in IR
    "This maps to Inline::Strong @ bytes [9, 16]"
    ↓
    Show formatting indicator


Current Workaround: Block-level precision only
  - User at line N
  - Match to Block with start_line <= N <= end_line
  - Within that block, infer inline position from content
  - Less precise but sufficient for many use cases
